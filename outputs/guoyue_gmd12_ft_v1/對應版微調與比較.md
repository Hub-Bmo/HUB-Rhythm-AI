# 國樂樂器對應 GMD 類別：第二次 Fine-tuning 結果

已使用原始 GMD Transformer 重新初始化並完成獨立微調。第一版國樂模型、第一版 token 與六份來源 token 都保留。

## 本次轉換

六首作品中實際有32個國樂樂器分類，全部映射到GMD既有12類的候選集合，實際使用11類。hihat_pedal沒有對應。完整逐項理由與判斷把握見「樂器對照表.md」。這是功能／近似音色的實驗假設，不宣稱兩種樂器相同；部分專名仍需實際音色確認。

替換的是 `<INST:C...>` → GMD 原有 `<STROKE_...>`，不另外建立平行的樂器ID。其他token、loss_mask、來源順序、小節、時值、輪奏、重音、裝飾音、延音、起音皆逐項保留。多件樂器同時映射到同一個GMD類別時，事件仍全部保留，不去重。

新資料位置：`outputs/guoyue_gmd12_tokens_v1/`。`sequences_all.jsonl`包含原始132段、62,389 tokens、5,316個樂器事件；`sequences.jsonl`沿用第一輪實際訓練／驗證的130段、61,933 tokens、5,284個樂器事件。原先排除的2段跨切分相同序列仍排除，投影後沒有新增跨切分完全相同序列。

## 控制條件

兩版使用同一原始GMD checkpoint、同樣5首訓練／黃土情完整驗證、相同資料列與順序、相同200-token詞彙表和ID、同樣模型尺寸、seed 42、60 epochs、batch 8、最高學習率0.00003、warmup 20、patience 10、AdamW與BF16。只有樂器輸入與目標token替換。

維持200-token詞彙表是為了控制模型大小與隨機初始化；舊INST分類仍保留在詞彙表，但不出現在本次資料的輸入或目標。這份資料仍沿用國樂 EVENT／BAR 等格式，沒有把它重新設計成原GMD的STROKE／VEL完整語法。

兩版皆在相同的6,483個已知驗證目標上計算；樂器有534個、時間間隔549個、時值534個。未知欄位與padding不計入loss或正確率。

共同樂器尺度：將第一版的32個INST分類及原有STROKE輸出機率，依同一映射加總到12個GMD類別；非樂器token合為無效輸出類。對應版也採相同計算，避免直接把32類正確率與11類正確率當成同一任務。

這次映射讓粗分類樂器與時值預測有所改善，但時間間隔預測變差。整體loss降低也包含目標分類變少的影響，不能直接推論生成節奏更好。結果只來自一個seed、黃土情這一首驗證作品；尚未進行自由生成試聽或獨立測試集評估。較細的國樂樂器身分已在此表示中合併，單靠新token無法還原這些差別；原始資料與對照仍保留供追溯。
