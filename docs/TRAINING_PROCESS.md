## 保存的過程

1. GMD：原始MIDI及metadata → 原始轉換程式 → 事件CSV → STEP／HIT_SET／STROKE／VEL序列與133個詞彙 → V1 Transformer。CSV以gzip無損保存。
2. 國樂：原圖與辨識／校對專案 → 六首已整理JSON及完整規則工作庫 → 132段原始token → 排除訓練側兩段完全重複資料 → V2實際130段訓練與驗證序列。
3. V2：保留原GMD token ID，再擴充國樂欄位，得到200個詞彙；從保存的V1初始化。五首作訓練，黃土情整首作驗證。
4. V3：使用相同切分、相同200詞彙及其餘欄位，把樂器投影為GMD類別；另外從同一份V1初始化。完整映射理由在outputs/guoyue_gmd12_tokens_v1/樂器對照表.md。

每個正式模型目錄保留config.json、history.json、summary.json、console log、當時程式快照、最佳checkpoint與可續訓的last.pt。詳細參數見[實驗紀錄](EXPERIMENTS.md)及experiments.json。
