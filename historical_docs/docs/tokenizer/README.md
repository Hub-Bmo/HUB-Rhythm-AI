# 國樂資料 Token 化工具 0.1.0

雙擊根目錄的 `啟動TOKEN化工具.bat`。只使用 Python 標準函式庫與 Tkinter，不需網路、API key 或新增套件。

這是獨立工具，不修改原有辨識、校對、播放程式或來源 JSON。

## 基本操作

1. 在「作品」匯入一份或多份 `musicai-reviewed-training` 1.0 JSON，用 Ctrl／Shift 選擇這次要輸出的作品。
2. 在「對應規則」查看樂器。選擇來源列後，可指定既有標準分類、建立新分類，或以「樂器依原名建立並確認」保留名稱。多選可一次對應到同一類。
3. 音高／擊法等來源標記可以依作品保存規則；共用規則可供後續作品自動套用。本作品規則優先。新項目不會因名稱相似而自行合併。
4. 在「輸出欄位與合併」勾選本次需要的欄位。預設開啟時值、速度；輪奏、重音、裝飾音、音高、擊法等先關閉。
5. 使用「另存為新設定」建立例如「含輪奏版」。各設定保有自己的欄位選擇與輸出合併方式。
6. 在「預覽與匯出」更新預覽。啟用欄位的已見標記若沒有對應，會阻止匯出並列出項目；尚未啟用的欄位不阻擋。
7. 匯出時選一個上層資料夾。每次建立新版本資料夾，不覆寫來源或舊輸出。

「樂器依原名建立並確認」只處理你選取的樂器列，是明確的人工作業。程式不會在匯入時自動認定所有新名字代表不同樂器。

## 定音鼓、中文與不同記譜方式

中文名稱只是可讀標籤，正式 token 使用穩定分類編號；詞彙表保存中文說明。

樂器、音高／鼓位、擊法／音色變體分開處理。`132`、`ABC` 和五線譜沒有預設互換規則。已確認實際 MIDI 音高的來源以 `MIDI:48` 等形式列入清單；已知音級保留音級、八度位移與升降記號；其餘保留原文供人工對應。標準分類可命名為「MIDI:48」「音級 1」「低音鼓位」等，名稱由你確認，不會因輸入名稱而替其他未知事件補音高。

來源 JSON 若已將不同原始符號轉成完全相同的結構化資料，工具會沿用這些資料。若符號只剩圖片、或原始欄位並未保存必要資訊，必須回校對工具補充，不能從 token 工具復原不存在的資料。第一版不是辨識圖片的程式。

相同來源名稱可建立共用別名規則；音高與擊法的共用規則另限定相同來源樂器名稱，避免把另一種樂器的 `A` 誤套用。本作品規則限定目前匯入的內容快照；重新校對後匯入的新快照需重新確認作品專用規則，共用規則可沿用。

## 真實身分與訓練合併

標準化「大鑼」仍是大鑼。要在某個實驗把大鑼輸出成小鑼，請在該輸出設定的合併表指定，不要把來源身分改成小鑼。另一組設定可保持分開。

合併形成的相同同時事件會全部保留，列入 `report.json`，不自行去重。切換設定或恢復各自輸出即可重新匯出。

## 固定骨架與未知欄位

固定保留 PPQ 960、時間位置、拍號、小節與段落邊界、同時事件群組、起音／續接狀態。每個段落是一個序列，依段落 `playback_order` 展開，不按小節號重新排序。變拍號、開頭空白、事件之間空白、空白小節及小節末尾時間均保留。時間分數以四分音符為單位，精確乘以 960；不將分數誤當來源 tick，也不自動四捨五入。

格式示例：

```text
<BOS> <SEGMENT_START>
<BAR> <METER_4/4> <TEMPO_144>
<TIME_SHIFT_0> <HIT_SET>
<EVENT> <INST:C00001> <ATTACK_YES> <DURATION_1440> <END_EVENT>
<EVENT> <INST:C00002> <ATTACK_YES> <DURATION_1920> <END_EVENT>
<END_HIT_SET>
...
<END_BAR> <SEGMENT_END> <EOS>
```

這是國樂 tokenizer v1 的獨立格式，尚未與先前 GMD 的 `vocab.json`、HIT_SET grammar 對齊。GMD checkpoint 不能直接使用這個詞彙表，後續需以實際 GMD 檔案驗證與接軌。現有 GMD tokenization 未被改寫。

選填欄位關閉時，不產生該欄位的 token，但工作庫仍保存所有原始欄位。關閉輪奏不會將輪奏展開成連打，生成資料因此也不包含輪奏演奏資訊。開啟欄位時：

- 來源 `training_mask=true` 的已知布林值區分 true 與 false。
- 沒有值或尚未確認的值輸出 UNKNOWN token，對該位置設 `loss_mask=0`，不當作「沒有」。
- 已見但尚未對應的文字會進入待確認清單。明確保存人工對應，才可將原本未確認的文字轉成標準分類。
- 時間起點是固定骨架，未知起點不能匯入，需回校對程式補妥。
- 續接事件輸出 `ATTACK_NO`，不偷偷轉成新的敲擊；起音未知則輸出 UNKNOWN 並遮罩。

這裡的 `loss_mask[i]` 對應 `token_ids[i]`。自回歸訓練使用 `inputs=ids[:-1]`、`targets=ids[1:]`、`target_mask=loss_mask[1:]`，損失只計入 target_mask=1 的位置。這不是 attention mask，未遮罩的 padding 或未對齊的 target mask 都可能造成錯誤訓練。

原始符號、圖片資訊與來源等可能保留在 provenance 或工作庫，不是訓練 token；訓練器只能讀指定的 token_ids 與遮罩。

## 工作庫與版本

預設工作庫：`projects/tokenizer-workspace/tokenizer-library.json`。包含來源完整快照、已見項目可重新建立的資料、標準分類、人工規則、輸出設定與累積詞彙表。重開程式會載入。

「備份工作庫」可輸出完整備份。恢復時，在另一個資料夾放入命名為 `tokenizer-library.json` 的備份，再按「開啟其他工作庫」。搬移電腦不依賴原始 JSON 路徑仍存在；快照已保存。

每次匯出包含：

- `sequences.jsonl`：token 文字、數字 ID、loss_mask、來源事件與演奏時間軸。
- `vocab.json`：穩定 token ID 與標準分類標籤。新 token 只附加，不重新排序；過去使用的欄位即使本次關閉，其詞彙 ID 仍可能留在累積詞彙表中，但不出現在本次序列。
- `rules.json`：該次規則、標準分類與輸出設定快照。
- `manifest.json`：來源內容雜湊、版本、PPQ、設定、詞彙表與規則雜湊、遮罩使用方式。
- `preview.txt`：完整可讀 token 對照。
- `report.json`：合併碰撞與注意事項。

同一作品、同來源套件與重複引用的小節應留在同一訓練切分，工具不將它們隨機拆成訓練／驗證集。`group_id` 保存來源套件 ID（沒有則退回校對 ID／快照 ID），由後續訓練器據此切分。

改欄位或合併設定須重新匯出；不會改動已匯出的資料或已訓練模型。重新命名標準分類保留固定編號。工作庫儲存時會檢查版本；若另一個視窗已更新，需重新開啟工作庫後再修改。請避免同時編輯同一工作庫。匯出過程使用 `.pending-` 暫存資料夾，只有完整完成後才改為正式 `tokens-` 資料夾。

## 命令列與驗證

```text
python tokenize_scores.py --workspace projects/tokenizer-workspace --import projects/sheetData/JCHW.json
python tokenize_scores.py --workspace projects/tokenizer-workspace --export outputs/tokenized
python -m unittest tests.test_score_tokenizer tests.test_score_tokenizer_ui
```

命令列匯出使用該工作庫目前保存的設定與所有作品；仍會檢查待確認項目，不會代替你猜測或確認對應。
