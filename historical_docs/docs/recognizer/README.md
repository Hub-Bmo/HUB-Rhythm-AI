# MusicAI 樂譜辨識程式 A（第一版）

這個程式匯入整份樂譜照片，登記紙面小節與辨識範圍，透過 OpenAI 產生待核對資料。
人工補填、樂器／技法確認、音效播放、段落劃分由獨立 [程式 B：校對與試聽](../reviewer/README.md) 負責，從根目錄 `啟動校對與試聽.bat` 開啟。

## 開啟

PC 程式 A 新增本機 OMR、四角斜框與模型下拉選單；仍由原本的啟動檔開啟。操作與試讀限制見 [PC 本機 OMR](PC_OMR.md)。Mac 的程式 C 維持獨立副本。

- 雙擊專案根目錄的 **啟動樂譜辨識.bat**。
- 想先練習操作，雙擊 **開啟樂譜辨識範例.bat**。本機範例已匯入使用者提供的第 1、2、3、4、25 頁；框線為初步位置，尚未確認或呼叫 API。
- 首次啟動會在 `.venv-recognizer` 建立獨立 Python 環境、安裝 `requirements-recognizer.txt`。需要 Python 3.10 以上及 Tkinter；本機也可使用 Codex 已安裝的 Python。
- 舊版仍從原本入口開啟；新版不修改舊專案。

## 操作流程

1. **新增專案**，輸入曲名後按「建立專案」，程式預設在 MusicAI 的 `projects/` 內自動建立專案資料夾，不必在系統視窗按「新增資料夾」。也可選擇其他存放位置；若存取被拒，改用預設位置或另一個可寫入位置。建立後再匯入連續 JPG／PNG。照片複製到工作專案，可搬移整個資料夾。
2. 檢查左側頁序。檔名採數字排序，例如 1、2、10；「改頁碼」登記紙面頁碼，↑↓ 調整頁序。
3. 按「新增範圍」，在圖上框選整個節奏樂器區，包含左側名稱及演奏記號。同頁多個譜表系統可各建一個範圍。
4. 填寫起始小節、小節數、譜種。簡譜、五線譜、鑼鼓經可選，亦可自動判斷。拍號、調號未知可留白；初版不會自動跨頁套用拍號。

   PC 版可先在右側「新範圍預設」選擇 5、8 或其他小節數，選好會自動記住；這份專案後續新增範圍就沿用，重開仍保留。已登記範圍及其辨識結果不更動。遇到少數頁不同小節數，直接修改該範圍的「小節數」即可，不會改掉預設。

   用「拆成逐小節」後，可按「確認本頁所有拆分小節」，一次確認目前頁面所有拆分出的範圍，不必逐筆按確認。此按鈕不確認其他頁面、不送出 API；確認後再選擇引擎與批次辨識。拆分後使用「OpenAI（整個所選範圍）」時，每個範圍就是一小節，送出前仍會顯示請求清單及計費確認。
5. 若改小節數，按「依小節數重排分界」。拖曳橘線對準實際小節線；第一條線是音樂開始處，樂器名稱位於其左側。最後一條線是最後小節終點。
6. 如需上方拍號、調號、速度、反覆資訊，用「框選參考資訊」框取該區。若分散於整頁，可將參考框涵蓋整頁。第二張圖只提供脈絡，節奏仍以主範圍為準。脈絡不在本頁時，可填「樂譜共通資訊」或範圍補充。
7. 「裁切預覽」可看實際送出的乾淨圖片；畫面橘線的正規化位置會另外作為小節分界資料送出，並不直接畫在原圖上。
8. 按「確認範圍與分界」。畫框、拖線、改參數後都要重新確認，舊辨識不會被刪除。
9. OpenAI 設定輸入 API 金鑰與有權限使用的影像模型。金鑰可只留在當次記憶體，也可選擇系統憑證保存。專案不保存金鑰。
10. 按「辨識目前範圍」或「辨識所有已確認待辦」，確認來源摘要後送出。每個範圍是一個 API 請求，逐筆執行、逐筆保存，單筆失敗不會停止後面項目。
11. 「查看結果／待確認項目」顯示聲部、小節、原譜符號、時間及疑問；點選結果可定位原圖。反覆與警告另有頁籤。
12. 匯出 `.recognition.zip`。套件包含原圖、完整辨識歷史、原始回應、時間、未知資訊與未完成狀態，供程式 B 使用。

辨識開始前會檢查來源頁序與已登記的小節順序。新增範圍目前依建立先後接續小節號；若逆向逐頁框選，或事後調整照片順序，可能出現後一頁反而使用較小號碼的情況。程式會停止送出並列出問題位置，應先對照原譜整理編號；已有的辨識與人工校正不應因此直接刪除重做。

`score_recognizer/numbering_repair.py` 提供成對離線修復：依目前頁序及各頁已登記的小節數重編 A/B，保留有效辨識、人工修改、接受／排除狀態及原始回應。執行前必須保存、關閉 A/B，先預演並比對原譜小節標號，再以獨立資料夾備份兩份 manifest。工具會檢查同一來源、並行保存及正在辨識的工作；目前不自動搬移已有的人工段落或反覆區間，遇到這類專案會停止而不改檔。

## 範圍反覆逾時時

每次辨識等待回應的設定為約 5 分鐘，逾時不等於收到辨識內容後驗證失敗。先查「查看結果／待確認項目」的錯誤；若是 APITimeoutError，可選範圍，按「拆成逐小節（舊結果留存）」。程式使用已登記小節線，建立一小節一範圍的草稿，原範圍與歷史回應封存，不會自動呼叫 API。

第一個小節保留原左側名稱區；其他小節以原範圍或既有參考框作背景圖，以讀聲部名稱及變拍。已成功的 OMR／OpenAI 範圍也能如此拆分重做，舊結果仍保存在辨識歷史，不會複製成新小節的答案。正在辨識中的範圍仍須等回應保存後再拆分。檢查裁圖後可用「確認本頁所有拆分小節」，選「OpenAI（整個所選範圍）」再送出。

若舊範圍曾匯入 B，請先保存並重開 B 再匯入後續結果；舊範圍的人工校對封存，保留原修改與接受狀態，新小節以待核對候選接替，避免新舊事件重複。原有段落定義保留，受影響的反覆核對需重新確認。若只想以原範圍重新辨識，不必刪除或拆分，選好 OpenAI 後按「辨識目前範圍…」即可。

《節慶歡舞》JCHW-22.jpg 的 85–88 小節當時有三次 APITimeoutError，均約 5 分鐘，raw_output 為空。這只證明沒有在時限內收到結果，無法由本機紀錄判定是網路還是服務端處理時間。拆小可減少單次輸出工作量，但不保證消除所有逾時。

## 畫面圖例

- 藍框：已保存的主辨識來源。
- 橘線：小節分界，支援拖曳。這不是樂句／訓練段落。
- 紫框：參考資訊來源。
- 綠框：辨識結果提供的證據位置，仍需人工核對。
- 滾輪：捲動；Ctrl＋滾輪或＋／－：縮放。

## 結果狀態

「已辨識・待核對」不代表音樂內容已確認。全小節休止有獨立紀錄，與空結果／漏辨識區分。
未知樂器或技法保留原始名稱、符號和節奏，不新增到全域樂器庫、不靜默略過。
「預期樂器」可幫助檢查漏回報，但不同別名會產生提醒，需要人工確認。
空結果可使用「辨識目前範圍」重送；批次待辦不自動重送成功或空結果。

更動來源或共通資訊後，辨識顯示「來源已改・需重辨」。批次中斷不會在重開後自動連線；請自行重試。
「停止後續辨識」會等待目前請求完成並保存，不丟棄已送出的回應。

## 驗證範圍與現階段限制

- 已以離線模擬回應驗證格式、來源座標、未知樂器、休止、變小節數、跨頁反覆、重開及可攜匯出；Tk 測試涵蓋欄位保存與裁切預覽。
- 五線譜已有專用音高、譜號、升降記號、延音／連奏資料及提示詞。實際五線譜辨識準確率仍需代表性譜面驗證。
- 本機已有使用者實際批次試跑的資料；離線測試通過仍不能代表每份譜的讀譜準確率，需透過程式 B 對照原譜核對。
- 第一版由使用者框選範圍並確認分界；不使用舊介面的自動段落／小節偵測。
- 同一小節批次只登記一次。若同頁分成多個系統，請分配各自連續且不重疊的小節號。
- 辨識套件是新格式，不支援在舊版直接開啟，也不直接輸出正式訓練資料。程式 B 可直接讀取此專案的 manifest 或匯出 zip。
- 原圖是使用者提供的作品，僅保存在本機忽略追蹤的 `examples/local-scores/`。
