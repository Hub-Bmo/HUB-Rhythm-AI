# PC 程式 A：本機 OMR

PC 的程式 A 現在也支援 OMR；Mac 移植則維持獨立的程式 C。程式 B 的校對與播放程式碼未修改。
更新前的 PC A 已備份到 `backups/recognizer-before-omr-20261028/`，原本的樂譜專案、API 設定與金鑰沿用，不需換成程式 C。

## 這台 PC 的操作

1. 等目前的辨識工作完成並保存後，關閉程式 A，再雙擊原本的 **啟動樂譜辨識.bat**。既有視窗不會自動載入新按鈕。
2. 按上方 **本機 OMR 設定**，這台已放好 Audiveris，應會自動找到。只需確認路徑，不必另外操作 Audiveris 介面。
3. 開啟辨識專案，先選一小段清楚的**印刷五線譜**試跑。簡譜、手寫譜維持使用 OpenAI。
4. 框選所需聲部，填起始小節與小節數。照片傾斜時按 **調整斜框** 拖動四角，按 **裁切預覽** 看攤正結果。
5. 按 **拖曳小節線** 對齊橘線，再按 **確認範圍與分界**。
6. 右下方辨識方式選 **本機 OMR（印刷五線譜）**，按 **辨識目前範圍…**。這一步只在本機處理，不產生 OpenAI API 費用。
7. 按 **查看結果／待確認項目**，查看 **OMR 疑問與處理紀錄**。若本機已有可對齊結果，可改選 **OpenAI（只補辨 OMR 疑問小節）**；若 OMR 本身失敗，先調整裁圖，或明確選 **OpenAI（整個所選範圍）**。

OpenAI 仍須確認送出，會依 API 用量計費；不會因 OMR 失敗自動改用付費辨識。
OpenAI 設定裡可用下拉選單選擇 Luna（gpt-6-luna）、Terra、Sol、Astra，也保留原本已存的模型。選好後按「保存設定」；不會自動送出辨識。

## 現階段限制

2026-10-28 修正 Windows 文字辨識元件無法讀取中文資料路徑的問題：程式會自動將公開語言資料快取到可讀取的英文路徑，原譜與專案不用改名或搬移。更新後需重新開啟 A；此修正不代表聲部分組已正確。

同日另修正語言資料格式：Audiveris 使用 legacy 辨識模式，須使用官方 `tessdata` 相容資料；只有 LSTM 的 `tessdata_fast`／`tessdata_best` 不能用。程式會先檢查格式，避免等到整頁跑完才發現文字辨識無法啟動。

本機 OMR 現在會先加強淡線；若聲部分組與登記小節數不符，且原圖確實存在跨聲部的淡連接線，會自動加深該線後再試一次。兩次都只在本機執行，保留原始裁圖與處理紀錄，不憑空添加原圖不存在的連接線。
以使用者第 2 頁複本測試，新流程約 27 秒產生五聲部、各五小節的候選，並已驗證程式 B 可匯入。樂器名稱、拍號與音符準確性仍待核對；這不是正式訓練資料。

斜框可以減少相鄰聲部混入，無法補回模糊或被切掉的符號。框選時保留樂器名稱、譜號、拍號、符頭、符尾與連線。
本次《天下無雙》翻拍譜試讀仍有聲部分組錯誤；OMR 是試用功能，不能保證這批老譜都能正確辨識。
本機的結構檢查也不能證明沒有漏音；結果一律仍待校對。先試一頁，確認可用再處理整份。

兩個系統的分工是：**A：PC 辨識（OMR／OpenAI） → B：PC 校對與試聽**；**C：Mac 辨識（OMR／OpenAI）**。
同一份專案不要同時在兩個視窗或兩台電腦編輯。

## 逐小節送 OpenAI 的操作

在右側「新範圍預設」先選 5、8 或其他小節數；選好即保存到這份專案，後續新增範圍與重開程式都會沿用，不改已登記範圍。
框選並對齊原譜後，可用「拆成逐小節」，再按「確認本頁所有拆分小節」一次確認本頁的拆分範圍；其他頁面與未拆分範圍不受影響，也不會自動發送辨識。

已有成功 OMR 結果也可以按「拆成逐小節（舊結果留存）」重做；原範圍與回應封存，新小節不沿用舊 OMR 答案。正在辨識的範圍仍不能拆。匯入 B 前請保存並重開 B，以使用新的範圍接替邏輯，舊校對封存而不與新候選重複。
之後選「OpenAI（整個所選範圍）」，拆分後每個範圍就是一小節，再依確認清單送出。批次「所有已確認待辦」可能包含其他已確認頁面，送出前請看清清單。

2026-10-28《闖將令》的手抄譜試跑，最新第 34 頁登記 9 小節，本機只辨出各聲部 1 小節；語言資料已載入，仍因小節結構不符而擋下。
該譜混合五線、單線打擊記譜，小節線及簡寫符號也較淡。[Audiveris 官方明列不支援手寫譜](https://audiveris.github.io/audiveris/_pages/handbook/)，這份建議逐小節使用 OpenAI，再人工校對，不必反覆重跑 OMR。
