# 樂譜模型比較工具（獨立 PC 工具）

雙擊 MusicAI 根目錄的「啟動模型比較工具.bat」。沿用 PC A 已安裝的 Python 套件，另用 `score_comparator/` 與 `comparison-project.json` 保存比較工作，不改程式 A、B 或 Mac C。A、B 的啟動方式維持原狀。

## 最快開始

1. 按「複製 A 的照片與範圍…」，選原辨識專案的 `recognition-package.json`，輸入比較專案名稱。預設在 `projects` 自動建立獨立 `.score-comparison` 資料夾，照片與範圍複製進來，原專案只讀。原先的模型答案不混入本輪比較。
2. 選頁面及範圍。框選、拖橘色小節線、斜框四角、參考框、拍號調號與預設小節數的操作與 A 相同。改小節數後先按「依小節數重排分界」，對準原譜後按「確認範圍與分界」。也可以「新增比較專案」直接匯入 JPG／PNG。
3. 在「模型／金鑰設定」勾選模型。預設 Terra 與 Luna；另有 Sol、Astra，可加入其他支援圖片與 JSON Schema 的 OpenAI 模型 ID。預設圖片 high、推理 medium；設定只存本比較專案。金鑰留白時沿用當次、環境變數或系統憑證；新增金鑰預設只留記憶體，可自行選擇系統憑證保存。
4. 在右下的小節清單選一個或多個小節（Ctrl／Shift 複選，或「選取本範圍全部小節」）。按「比較所選小節…」。例如 3 小節 × 2 模型就是 6 次付費請求，送出前會再次列出小節、模型、圖片與推理設定。取消不送出。
5. 在「模型結果與差異」選比較紀錄。上方是實際送出的圖片快照；下方選左右模型，並排看樂器、敲擊／休止、拍點、時值、原符號、音高、輪奏等。點事件可在主圖顯示模型提供的證據框；可放大圖片核對，框位置本身也可能不準。
6. 「差異清單」標示不同欄位或只有一邊列出的事件；完整回應頁保留原始輸出、反覆、未知細節與錯誤。可以保存人工比較筆記。按「匯出比較報告…」輸出模型用量、事件及差異摘要 CSV，以及完整比較紀錄 JSON。

## 如何解讀

- 每個小節的主圖、參考圖、指令、輸出結構及設定固定。每個模型獨立收件，彼此不會看到對方的答案。請求範本與圖片放在 `cases/比較編號/`，可追溯實際輸入。
- 目前是結果差異比較，不是準確率評測，也沒有用舊答案訓練或提示模型。兩模型一致可能一起出錯；「較接近原譜」筆記不等於已建立每個事件的正確答案。
- 比對將等值分數視為相同，先找完全一致的事件，剩餘在同聲部依順序提供候選配對。額外／缺少音符不會使已一致的所有後續事件都變成不同；但候選配對仍可能不準，聲部名稱不同也可能造成額外差異。原符號包含在比對內，框位置與疑問措辭不計入音樂差異。
- 未知不是「否」，空結果不是全休止；格式無效、失敗或尚未回應不能當成沒有音符。結構可讀也不代表音樂正確。
- 秒數是每次請求在本機觀察到的 API 往返時間。用量以伺服器回報為準；價格按 2026-10-28 官方一般輸入／輸出單價粗估，未扣快取且未計服務層級、長上下文或區域加價，非帳單。未知模型或未回報用量顯示未知，不能當零費用。
- 推理設定相同不代表各模型消耗相同運算量。選 default 使用各模型預設，條件較不一致；建議先使用共同支援的 medium。其他模型不一定支援所有設定，不支援會顯示錯誤而不自動替換模型。

## 保存與停止

每個模型收到回應後立即保存，格式檢查不通過也保存原始回應與已取得的用量。沒有自動重試、沒有自動轉交其他模型。「停止後續比較」只停止尚未送出的請求；在途回應仍會等待並保存，單次約 10 分鐘逾時。逾時未收到用量不表示伺服器沒有處理或計費。重新開啟後，在途工作標中斷，未送出工作標停止，均不自動重送。

若資料形狀可讀但時間超出小節，仍顯示候選事件與結構錯誤，方便找出兩模型的差異；欄位不完整或不是唯一單小節時，只能檢查完整原始回應。可在結果頁按「只重試此筆失敗模型…」，列出需付費重送的模型後，再手動確認；成功模型的答案保留、不重送。失敗的舊次回應及用量會封存，匯出用量表以「工作編號」「先前嘗試」區分，避免漏算先前可能已計費的請求。重試沿用原固定圖片與設定；若要改範圍或設定，請建立新一輪比較。

再次比較會新增一輪紀錄與費用。修改框選後舊圖片／結果仍保留，畫面標示舊快照。報告 CSV 是檢查用快照，不會回寫 A／B 或成為訓練資料；報告 JSON 不含原圖與固定請求檔，要保留完整實驗請備份整個 `.score-comparison` 資料夾。同一比較專案限單一視窗編輯，不要在兩台電腦同時寫同一 OneDrive 專案。
