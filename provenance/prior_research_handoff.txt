GMD → 國樂／北管節奏生成模型

跨對話研究交接資料

以下是目前「AI 音樂／節奏生成」專案的研究脈絡與目前進度。請將此內容視為前一個對話的工作背景，後續直接延續，不要重新從零設計。

一、研究目標

目前研究方向是：

使用 GMD（Groove MIDI Dataset）作為大型基礎節奏資料，先訓練一個通用的打擊樂節奏生成模型，再利用國樂／北管資料進行 Fine-tuning，使模型逐漸學習國樂／北管的節奏語法。

最終希望做到：

模型可以持續生成節奏。

不只是單一 4／8 小節，而是可以連續生成。

GMD 提供一般打擊樂節奏的基礎能力。

國樂／北管資料進一步調整模型，使其具有國樂節奏特徵。

未來可以加入國樂專屬的打擊樂器與演奏方式。

最終可能需要建立「模型 Token → 真實北管／國樂聲音」的 renderer 或 sample mapping。

二、目前最重要的資料表示概念：一個時間點可以同時有多個打擊事件

這是目前研究中特別重要的決定。

我們認為：

「一個事件（event / HIT_SET）」應該代表同一個時間點上，可以同時發生的一組打擊樂器事件。

例如同一個 tick：

Kick
Snare
Cymbal

可以同時發生。

因此 Token 化時使用：

<HIT_SET>
<STROKE_kick>
<VEL_4>
<STROKE_snare>
<VEL_6>
<STROKE_crash>
<VEL_5>
<END_HIT_SET>

而不是把同一時間點拆成三個不同時間事件。

這個概念與目前 GMD 的資料表示方式相符。

三、原始資料 Track 與模型資料的關係

目前討論的結論是：

原始資料

可以保留不同樂器的 Track：

Piece
├── Track 1：鼓
├── Track 2：鑼
├── Track 3：鈸
└── ...

這樣保留原始音樂結構與樂器資訊。

進入模型之前

再按照 tick 將不同 Track 的事件合併：

Track 1
Track 2
Track 3
   ↓
依 tick 排序
   ↓
相同 tick 合併
   ↓
HIT_SET
   ↓
Token sequence

因此推薦：

原始資料可以分 Track 保存；模型輸入則使用「同一時間點可包含多個 Event」的 HIT_SET 結構。

不要為了模型輸入而強迫每一個樂器變成獨立的序列。

目前使用：

<TIME_SHIFT_240>
<TIME_SHIFT_480>
<TIME_SHIFT_720>

<TIME_SHIFT_0>

TIME_SHIFT
    ↓
HIT_SET
    ↓

    ↓
END_HIT_SET
    ↓

十二、重要：北管沒有直接 mapping 到 GMD 樂器

目前的設計不是：

北管 center → GMD kick

沒有這樣做。

而是：

      +
北管 vocabulary
      ↓

十五、為什麼目前沒有急著處理「北管樂器 → GMD 樂器」mapping？

因為目前研究的第一個問題是：

模型能不能從 GMD 的一般節奏能力，透過 Fine-tuning 學習北管節奏 Token？

而不是：

北管樂器到底應該對應 GMD 哪一個鼓？

這兩個問題應分開。

目前：

模型層
↓
北管 Token

以及：

聲音層
↓
北管 sample / synthesis / MIDI

可以分開處理。

十九、建議的 Transformer v1 初始架構

先不要做超大型 Transformer。

建議第一版：

Vocabulary ≈ 133
Embedding = 256
Transformer Layers = 4
Attention Heads = 8
Feed Forward = 1024
Dropout = 0.1

使用：

Causal Self-Attention

模型只能看到當前 Token 以前的內容，不能偷看未來 Token。

二十、為什麼 Transformer 可能適合這個研究

LSTM：

Token 1
  ↓
Token 2
  ↓
Token 3
  ↓
Token 4
  ↓
...

主要透過 hidden state 累積歷史資訊。

Transformer：

Token 1 ─┐
Token 2 ─┤
Token 3 ─┤→ Attention → 下一個 Token
Token 4 ─┤
Token 5 ─┘

可以直接學習較遠距離的 Token 關係。

對音樂而言，希望它可以更好地學習：

重複
呼應
樂句
節奏型
較長距離的節奏結構

但不能假設 Transformer 一定比 LSTM 好。

GMD 只有約 1150 segments，因此 Transformer 太大也可能過擬合。

二十一、Transformer 的重要概念

需要理解：

Token Embedding

把：

<STROKE_kick>

轉成向量。

Positional Encoding / Positional Embedding

讓模型知道：

Token 在第幾個位置。

Self-Attention

讓模型決定：

預測目前 Token 時，前面哪些 Token 比較重要。

Causal Mask

限制模型：

不能看到未來 Token。

Feed Forward Network

Transformer block 中進一步處理 representation。

二十二、目前研究上最重要的實驗架構

希望最終形成：

                GMD
                 │
      ┌──────────┴──────────┐
      ↓                     ↓
    LSTM                Transformer
      │                     │
      ↓                     ↓
GMD-LSTM             GMD-Transformer
      │                     │
      ↓                     ↓

北管 Fine-tune         北管 Fine-tune
│                     │
↓                     ↓
北管生成模型            北管生成模型

這樣可以研究：

LSTM 與 Transformer 哪一種架構，更適合從一般打擊樂資料學習後，再 Fine-tuning 到國樂／北管節奏生成。

二十四、重要研究原則

後續不要因為 Transformer 比較新，就把現有 LSTM 架構全部丟掉。

目前 LSTM 是：

Baseline

Transformer 是：

新實驗模型

而 GMD 與北管的資料表示應盡可能保持一致，這樣模型比較才有意義。

另外，國樂／北管資料未來仍然非常少，因此目前的 4 segment 北管 Fine-tuning 只適合作為概念驗證，不能拿來宣稱正式模型效果。

最重要的資料表示原則：

同一個 tick 可以同時發生多個打擊事件，使用 HIT_SET 表示。

原始資料可以保留不同 Track；進入模型前再依 tick 合併成 HIT_SET。

最重要的模型原則：

不要把北管樂器硬 mapping 成 GMD 樂器；先讓模型學習北管自己的 Token。

最終聲音輸出則另外處理：

Model Token → 北管 Renderer / Sample / MIDI

不要把「模型學節奏」與「最後發出什麼樂器聲音」混為同一個問題。
